# 广告素材发布前审核助手

## 项目简介

本项目用于广告素材投放前的风险初筛。运营人员可按客户、活动和渠道提交素材；系统识别图文内容，依据规则生成风险提示、判断依据和修改建议，供审核人员复核。审核结果不代表已获发布批准。

网站首页 `/` 是统一工作台，`/batches` 为兼容地址。Excel 导入和手动补录进入同一服务端审核队列。审核员可跨批次筛选素材，查看原文件、识别文字和风险依据，记录人工通过、退回修改或待补证及处理原因。手动补录支持一条文案及最多4个图片/PDF文件；常规批量素材可使用 Excel 导入。

填写访问码后进入工作台，首先看到跨批次待审队列；选中素材后，在同一屏核对原始材料与风险依据并记录人工结论。点击“提交素材”打开 Excel 导入或手动补录弹窗，批次记录位于页面下方。任务在服务端继续处理，关闭网页不会中断已入队批次。单批最多100条、Excel最多20 MB；同一批中完全相同的图片组合可复用识别结果。页面提供5条不调用模型的本地规则样例，便于体验任务流转；该样例不代表 AI 审核效果。

上游系统可调用 `POST /api/batches` 提交纯文字素材，响应为 `202` 和批次编号；`GET /api/batches/<批次编号>` 查询进度，`GET /api/batches/<批次编号>/items/<素材编号>` 查询结果。图文批次使用 `POST /api/batches/excel`，手动补录使用 `POST /api/batches/manual`。接口示例与架构说明见 [BATCH_MVP.md](BATCH_MVP.md)。

批次数据保存在服务端 SQLite 中，默认24小时后清理。原始文件在此期间保留供人工复核；审核完成后从处理任务输入中移除，识别文字、审核报告和人工处理记录随批次一起保留至清理。当前为单进程、单实例实现；未配置持久磁盘时，重启或重新部署可能丢失批次。共享访问码和手填审核人名称不构成身份认证或客户隔离。接入真实客户素材前，需要完善持久存储、权限控制与数据处理方案。

支持文案、PNG/JPG/WEBP 图片与 PDF（含扫描件）。当前 A-01～A-10 规则只覆盖部分常见宣传风险，不能替代完整的行业、渠道和客户规则；清单见 `rules.json`，扩展方案见 [RULES_PLAN.md](RULES_PLAN.md)。未命中规则不等于合规或允许投放。

## 本地运行

建议使用 Python 3.12 虚拟环境。

1. 在项目目录创建虚拟环境：`python -m venv .venv`。
2. 如已有 `.venv`，可跳过创建步骤。
3. 运行 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`。
4. 根据 `config.example.json` 配置模型密钥和模型名称，可使用本地 `config.json` 或环境变量。视觉模型默认 `qwen-vl-plus`，实际以账户可用模型为准。
5. 运行 `.\.venv\Scripts\python.exe app.py`，浏览器打开 http://127.0.0.1:8765 。

## 操作步骤

- 点击“提交素材”后选择 Excel 导入：下载模板，按行填写文案并插入对应图片，上传后提交到审核队列。
- 在同一弹窗选择手动补录：填写一条文案，按需附加图片/PDF与补充资料，提交到同一审核队列。
- 在跨批次审核队列中按客户、活动、渠道、风险等级、机器状态和人工结论筛选素材。
- 打开素材详情，对照原文件与识别文字，记录人工结论和依据；失败任务可单独重试。

- 手动补录最多4个文件，合计8 MB、4页；PDF超限拒绝整份文件，不能只审前几页。
- PNG/JPG/WEBP需为静态图，最多2400万像素。大图缩小后会提示人工核对小字。PDF逐页渲染到最长边不超过2200像素。
- 图片/PDF识别需要视觉模型权限；文字模型 qwen-plus 的调用成功不代表视觉模型权限已开通。
- PDF全部页面都会送入视觉模型识别；任一页缺失，不生成成功的完整材料结果。识别可能需要几分钟，可能产生模型调用费用。
- 手动补录默认按本次提交材料处理，Excel 导入仍保留“完整性未确认”的保守标记；图片模糊、裁切等具体问题仍会触发A-10提醒。
- 暂不支持视频、音频、Word、Excel规则导入或证据附件核验。补充证据目前为文字输入。

## 审核原理与准确率

工作台正常提交的 Excel 和手动补录任务使用 `mode=ai`：图片/PDF先由视觉模型识别，文案与识别结果再交给文字大模型做语义判断。`rules.json` 提供当前十条审核标准及强制校验，`audit_prompt.md` 规定审查步骤与输出格式；规则优先于材料中的任何指令。“生成示例批次”才使用不调用大模型的本地关键词模式。模型名称可通过配置修改，默认文字模型为 `qwen-plus`、视觉模型为 `qwen-vl-plus`。

提取 → 检查完整性 → 逐项主张与证据匹配 → 跨页核对 → 按十条规则输出 → 程序验证。

- 本地模式仅匹配关键词，未命中不能视为合规。
- AI语义模式区分时序用语、商品参数和宣传承诺；不以“第一”子串直接判断“第一次使用”违规。
- A-06敏感词和A-10材料缺口由程序强制保留。
- 同一规则可以返回多个问题；引用必须存在于材料中，不能拼造原文。
- 图片任务中若 AI 引用无法与原文唯一对应，相关问题转为证据不足并要求人工对照原图；纯文字任务仍拒绝无法核实的引用。
- 补充资料中的来源、对象、时间、口径需要匹配，不能用一句“有报告”冒充证据。
- “详情以App为准”与大促活动不豁免A-03、A-04。
- 未独立验证来源、授权或模型识别正确性；视觉显著性只作初筛线索。当前所有结果都需人工确认，不自动放行。

提示词改进不等于已证明准确率提高。evaluation_cases.json包含14条边界样例。运行 `python evaluate.py --live` 会真实调用模型并产生费用，输出 eval-results.json，包括漏检、误报和失败数量；只评价已标注的规则对，不宣称总体准确率。扩充到50～100条人工标注样本，保留独立测试集，比较版本后再决定是否上线新提示词。

## 输出

整体结论、模式、规则/提示词版本、时间、完整性、是否拦截、人工审核、能力边界、十条规则检查状态。

每条问题包含原文、文件页码或文字位置、类型、对应规则、风险等级、判断依据、整改建议、待补充证据、人工审核要求。页码对应模型识别文字，不是像素框定位。缺失内容不能伪造原文，使用空引用和说明。

报告由批次接口返回，并在工作台中按素材查看。详情顶部先显示高风险、中风险、引用待核对或初筛未发现明显风险等摘要，再展示原始素材和逐条依据；“初筛未发现明显风险”不等于人工通过。机器初筛结果与人工结论分开保存，人工结论变更会留下操作记录。批次、原文件与报告按上文说明临时保存在服务端；AI服务商的数据处理条款另行适用。

## 测试

运行 `.\.venv\Scripts\python.exe -m unittest -v`。自动测试覆盖规则、AI返回校验、PDF全页处理、上传失败、访问码、敏感词和A-10。模拟模型测试不是实际AI效果评测。

self-test-results.json是第一版真实本地规则样例记录，不能当作v2多模态实测结果。新的测试情况见VALIDATION.md。
