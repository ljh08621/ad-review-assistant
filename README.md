# 广告素材发布前审核助手

## 批量审核工作台（面试 MVP）

打开 `/batches`，填写客户、活动、渠道和试用访问码，上传 Excel 后提交。服务端逐条处理，网页关闭后仍可继续；返回页面可查看批次进度、每条结果，并重试失败素材。单批最多100条、Excel最多20 MB。相同图片组合在同一批内复用识别结果。页面也提供5条不调用模型的本地规则样例，用于演示排队与状态流转；本地样例不代表AI审核效果。

上游系统可调用 `POST /api/batches` 提交纯文字素材，响应为 `202` 和批次编号；`GET /api/batches/<批次编号>` 查询进度，`GET /api/batches/<批次编号>/items/<素材编号>` 查询结果。图文批次可调用 `POST /api/batches/excel`。接口示例、限制和下一阶段架构见 [BATCH_MVP.md](BATCH_MVP.md)。

批次数据保存在服务端 SQLite 中，默认24小时后清理；上传图片在成功识别与审核后从任务输入中移除，保留识别文字和审核报告。当前为单进程、单实例演示；Render 未配置持久磁盘时，重启或重新部署可能丢失批次。共享试用访问码不提供真正的客户账号隔离。真实客户素材须在持久存储、权限与数据处理方案落实后再接入。

支持：文字粘贴、UTF-8 TXT、PNG/JPG/WEBP 图片、PDF（含扫描件）。只使用题目给定 A-01～A-10，不移植小米平台专属规则。

## 在 VS Code 运行

新增图片/PDF处理需要安装依赖，现在建议使用 Python 3.12 虚拟环境。

1. 在项目文件夹打开终端，先 Ctrl+C 停止旧服务。
2. 如果已有 .venv，不必重复创建；否则运行 `python -m venv .venv`。
3. 运行 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`。
4. 保留原 config.json 中的密钥、地址和文字模型，不需要重新粘贴密钥。视觉模型默认 qwen-vl-plus；可在 config.json 增加 `"vision_model": "qwen-vl-plus"`，以账户已开通的兼容视觉模型为准。
5. 运行 `.\.venv\Scripts\python.exe app.py`，浏览器打开 http://127.0.0.1:8765 。终端保持开启。

## 操作步骤

文字：粘贴文案 → 选择 AI 模式 → 勾选允许发送 → 开始审核。

图片/PDF：选择文件 → 勾选允许发送所选文件 → 识别文件 → 对照原件核对逐页文字（可直接修正错字，报告保留原始识别） → 勾选已核对 → 选择 AI 模式并提交审核。

上传文件与输入正文会合并审核。更换文件会清除旧识别结果；更改正文会清除旧报告。识别中的输入暂时锁定，防止把旧结果展示为新材料的报告。

- 单条审核最多4个文件，总计8 MB、4页；PDF超限拒绝整份文件，不能只审前几页。
- PNG/JPG/WEBP需为静态图，最多2400万像素。大图缩小后会提示人工核对小字。PDF逐页渲染到最长边不超过2200像素。
- 图片/PDF识别需要视觉模型权限；文字模型 qwen-plus 的调用成功不代表视觉模型权限已开通。
- PDF全部页面都会送入视觉模型识别；任一页缺失，不生成成功的完整材料结果。识别可能需要几分钟，可能产生模型调用费用。
- 勾选“完整”或“已核对”不会清除已识别出的模糊/裁切问题。A-10仍需补充清晰材料。
- 暂不支持视频、音频、Word、Excel规则导入或证据附件核验。补充证据目前为文字输入。

## 审核原理与准确率

rules.json保存十条原始规则；audit_prompt.md保存本项目的审查步骤、上下文例子与输出规范。规则优先于材料中的任何指令。

提取 → 检查完整性 → 逐项主张与证据匹配 → 跨页核对 → 按十条规则输出 → 程序验证。

- 本地模式仅匹配关键词，未命中不能视为合规。
- AI语义模式区分时序用语、商品参数和宣传承诺；不以“第一”子串直接判断“第一次使用”违规。
- A-06敏感词和A-10材料缺口由程序强制保留。
- 同一规则可以返回多个问题；引用必须存在于材料中，不能拼造原文。
- 补充资料中的来源、对象、时间、口径需要匹配，不能用一句“有报告”冒充证据。
- “详情以App为准”与大促活动不豁免A-03、A-04。
- 未独立验证来源、授权或模型识别正确性；视觉显著性只作初筛线索。当前所有结果都需人工确认，不自动放行。

提示词改进不等于已证明准确率提高。evaluation_cases.json包含14条边界样例。运行 `python evaluate.py --live` 会真实调用模型并产生费用，输出 eval-results.json，包括漏检、误报和失败数量；只评价已标注的规则对，不宣称总体准确率。扩充到50～100条人工标注样本，保留独立测试集，比较版本后再决定是否上线新提示词。

## 输出

整体结论、模式、规则/提示词版本、时间、完整性、是否拦截、人工审核、能力边界、十条规则检查状态。

每条问题包含原文、文件页码或文字位置、类型、对应规则、风险等级、判断依据、整改建议、待补充证据、人工审核要求。页码对应模型识别文字，不是像素框定位。缺失内容不能伪造原文，使用空引用和说明。

导出JSON或浏览器打印保存PDF。单条审核报告保存在当前页面，刷新清空；批量审核结果按上文说明临时保存在服务端。AI服务商的数据处理条款另行适用。

## 测试

运行 `.\.venv\Scripts\python.exe -m unittest -v`。自动测试覆盖规则、AI返回校验、PDF全页处理、上传失败、访问码、敏感词和A-10。模拟模型测试不是实际AI效果评测。

self-test-results.json是第一版真实本地规则样例记录，不能当作v2多模态实测结果。新的测试情况见VALIDATION.md。

## 给面试官使用

本机地址不能直接发给异地面试官。项目已有线上演示站；本地改动需要上传仓库并重新部署后才会出现在网站上。DEPLOY.md提供托管部署步骤。访问码与百炼密钥分离，面试官只拿网站链接和访问码。

## 配置与密钥

config.json只留本地，已加入.gitignore。服务端支持DASHSCOPE_API_KEY、DASHSCOPE_BASE_URL、QWEN_MODEL、QWEN_VISION_MODEL。AD_REVIEW_API_KEY可覆盖DASHSCOPE_API_KEY。公网使用APP_ACCESS_CODE（至少12位）和HTTPS。Docker不复制config.json。
